# 피드백

- 요구 사항을 정확하게 준수한다
- 기본적인 Git 명령어를 숙지한다
- Git으로 관리할 자원을 고려한다
- 커밋 메시지를 의미 있게 작성한다
- 커밋 메시지에 이슈 또는 풀 리퀘스트 번호를 포함하지 않는다 (프리코스 전용)
- 풀 리퀘스트를 만든 후에는 닫지 말고 추가 커밋을 한다
- 미션 제출 기간 이후에는 추가 커밋을 금지한다.
- 오류를 찾을 때 출력 함수 대신 디버거를 사용한다
- 이름을 통해 의도를 드러낸다
- 축약하지 않는다
- if, for, while문 사이의 공백도 코딩 컨벤션이다.
- 공백 라인은 문맥을 분리하는 부분에 의미 있게 사용한다
- 스페이스와 탭을 혼용하지 않는다
- 의도를 드러내기 힘든 경우에만 주석을 단다.
- 코드 포매팅을 사용한다
- Java API를 적극 활용한다
- 배열 대신 컬렉션을 사용한다
- 기능을 구현하기 전 `README.md`에 구현할 기능 목록을 정리해 추가한다.
- 기능 목록은 상세한 내용을 포함하지 않는다.
- 기능 목록은 **예외 상황도 함께 정리한다.**
- 기능 목록을 구현 과정에서 잘 변경한다.
- 기능을 구현하면서 문서를 지속적으로 업데이트하며 문서가 살아있도록 만든다.
- `README.md`를 통해 해당 프로젝트의 개요를 소개한다.
- 값을 하드 코딩하지 않는다.
- 클래스는 **상수, 멤버 변수, 생성자, 메서드** 순으로 작성한다.
- 변수 이름에 자료형은 사용하지 않는다
- 자료형은 코드 작성 시점에 자연스럽게 이해될 수 있도록 한다
- 한 메서드가 한 가지 기능만 담당하게 한다.
- 메서드가 한 가지 기능을 하는지 확인하는 기준을 세운다.
- 테스트를 작성하는 이유에 대해 본인의 경험을 토대로 정리해본다
- 처음부터 큰 단위의 테스트를 만들지 않는다.

## 공통 피드백 (가치관)

- **개발 환경과 프로그래밍 언어에 익숙해지는 것**
- 미션을 수행하면서 어려운 점이 있다면 테코톡을 통해 학습하고 구현해보기
- **'완벽하게 해내는 것'보다 '새로운 시도를 멈추지 않는 것'**
- 도전은 단순히 어려운 문제를 푸는 행위가 아니라, 자신이 아직 모르는 영역에 한 발 더 내딛는 태도입니다.
- 미션을 수행하다 보면 예상치 못한 오류나 막히는 순간을 여러 번 겪게 될 것입니다.
- 문제를 끝까지 탐색해 보는 경험이 바로 성장의 출발점입니다.
- 얼마나 탐색해야할지, 얼마나 도전해야할지 막연할 수 있다. **작은 도전부터 시작**
- 아직 익숙하지 않은 메서드나 문법을 하나 골라 적용해서 리팩터링해보기
- 에러를 만나면 바로 검색하지 말고 5분간 스스로 원인을 추측해 보기
- 디스코드에 ‘오늘 처음 시도한 것’ 한 줄 남기기
- **"할 수 있는 것만 하는 사람"이 아니라, "해본 적 없던 일에도 하나씩 도전하는 사람"**
- **함수 분리와 테스트 도구 사용법을 익히는 것**
- 어제의 나와 비교하며 자신만의 속도로 성장해 나가는 것
- 완벽한 결과물을 만드는 시험이 아니고, 얼마나 깊이 몰입하고 도전했는지를 경험하는 기간
- 8기의 핵심 키워드는 '도전'입니다.
- 완벽한 코드보다 중요한 것은 문제를 해결하기 위해 나만의 방법을 찾아가는 과정
- **이런 과정을 소중히 여기는 사람은 어떤 문제를 만나더라도 결국 해법을 찾아냅니다.**
- 작은 기능부터 차근차근 테스트를 작성해 나가다 보면 빠르게 익숙해질 거예요.
- 실패하거나 돌아가는 길도 괜찮습니다. 그 모든 흔적이 여러분의 몰입과 성장을 보여주는 소중한 발자국이 됩니다.
- 여러분의 도전 과정을 담아주세요.
  - 이번 미션에서 가장 오래 고민했던 부분과 시도들
  - 실패했지만 의미 있었던 도전
  - 다음에는 다르게 접근해보고 싶은 부분
  - 여러분만의 고민과 성장 과정
- 관련 함수를 묶어 클래스를 만들고, 객체들이 협력하여 하나의 큰 기능을 수행하도록 한다.
- 클래스와 함수에 대한 단위 테스트를 통해 의도한 대로 정확하게 작동하는 영역을 확보한다.
