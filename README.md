## 도메인 컴포넌트 소개

### Scenario: 정해진 순서대로 작업 수행
> `Scenario`는 `Runnable`을 구현하여 수행해야 하는 작업을 **순차적**으로 처리하는 데 집중합니다.<br>이를 통해 의도하지 않은 순서로 함수를 호출하는 경우에 발생할 수 있는 문제 상황들을 배제할 수 있습니다.

1. 로또 구매 후 보관
2. 당첨 로또 발매 후 보관
3. 당첨 통계 발급

### Manager: 도메인의 통신 인터페이스
> `Manager`는 도메인 내 특정한 유즈 케이스를 충족하는 것을 목적으로 고안된 일종의 브릿지 클래스입니다.<br>상태를 지닌다는 것이 특징이며, 이를 통해 도메인은 외부와 깔끔하게 분리되고, 반환 여부와 그 타입을 자유롭게 결정할 수 있습니다.

#### 🤔 출력이 달라져야 하는 경우를 어떻게 극복하나요?
- `Manager`가 `ViewModel` 객체를 반환하도록 수정해요
- `Scenario`는 전달받은 객체의 getter를 활용, 독자적인 로직으로 출력하면 돼요.

### 기타 컴포넌트
- LottoProblem: 본 도메인에서 발생하는 예외 상황의 종류
- Lotto: 구매한 로또
  - LottoRule: `Lotto` 클래스의 유효성 검증 규칙
- WinnerLotto: 당첨 로또와 보너스 번호 정보.
  - 보너스 번호는 `LottoRule`을 참조하여 검증된다.
  - `Lotto`에 대한 상품 변환 책임을 갖는다
- Vendor: 로또 구매
  - `Manager`의 가격 정보를 참조한다
  - 주어진 액수에 해당하는 로또를 모두 만들 수 없다면 예외를 던진다.
- Prize: 상품 정보
   - 해싱과 `Map`을 활용한 캐싱으로 역변환 과정을 효율적으로 처리한다.
   - 비교 연산을 정의하여, 깨지기 쉬운 기존 ordinal 방식의 정렬을 개선한다.
- WinningStats: 당첨 통계 및 수익률 (당첨 총액 / 투자 총액)
   - 계산 중 *DIVIDE_ZERO* 상황 또는 기타 유효하지 않은 상태에 예외를 던진다.
